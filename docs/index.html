00 / THESIS

先把“连续”
做成底座。

大多数 Agent 是一次性的：请求进来，回答出去，上下文清空。Tina 的假设相反——连续性不是提示词技巧，而是存储、调度与证据边界共同构成的基础设施。

问题

换一个窗口、换一台设备、重启一次进程，人格就开始漂移。模型记得的只是这次请求里被塞进去的东西。

记忆被当成“检索增强”，而不是“可追溯的原话 + 可演进的自我认知”。

做法

原话与 reasoning 进入只增不改的 sources.sqlite；自我画布、窗口账本与备忘进入同一个 Git 权威仓。

Host 只负责保真与可达；什么值得记、何时召回，交给当轮模型判断。

结果

同一份记忆可以被桌面、手机、语音、机器人等不同通道共享；换通道不等于换人。

代价是复杂度：SQLite、Git、压缩交接、World 生命周期，每一项都必须可回滚。

02 / MEMORY

原话不变，
理解可以生长。

记忆不是把聊天记录塞进向量库。它分成两层：不可变的一手原话，以及可演进的自我认知与备忘。两层都保留来源。

六个工具，MCP 与 HTTP 同源。压缩前先捕获原文与导航；不确定时 complete=false，原文仍然保留。

03 / WORLDS

通道可换，
“我”不换。

每个 World 是一个独立包，声明自己的工具、事件与配置模式。启用或停用不改宿主代码。

W.01CORE

console

Web 控制台。默认入口，承载对话、模型与工具调优。

W.02MOBILE

mobile

手机原文、持久回复与来源事实；发送是显式工具动作。

W.03VOICE

stt / tts

把音频转成文字，把文字合成语音；不采集、不播放。

W.04VOICE

audio-play

本机扬声器播放队列；取消只代表“请求取消”。

W.05HARDWARE

canbot

现实机器人观察与有界动作；物理完成始终保持 unknown。

W.06BRIDGE

codex-bridge

把任务交给 Windows Codex，按 operationId 对账。

W.07SANDBOX

linux-tools

bubblewrap 隔离执行；无网络、无宿主 home、无密钥。

W.08LANE

tinalink

主路与从路的事件联络；静默积累，显式唤醒。

W.09BOT

tina-main-bot

端侧主路 Bot 装配；保留 Core、Worlds 与原生记忆。

06 / QUICKSTART

能跑，
但要按步骤来。

这不是一条命令就能启动的 npm 包。第一次搭建请按 DEPLOYMENT.md 走。

  • OSUbuntu 24.04 · x86_64
  • Node24.12+（24.x）
  • pnpm11.28.6
  • AlsoGit · ripgrep · Python 3 · libzstd1
  • Network默认只监听 127.0.0.1

上游 Cortico 与 7 个 DSH 包是 MIT；本项目是 AGPL-3.0-or-later。第三方声明见仓库根目录。

bash / tina-foundation
# 1. 宿主依赖（全部来自 vendor/）
npm ci --ignore-scripts

# 2. 上游 Cortico
cd upstream/cortico
pnpm install --frozen-lockfile
pnpm run build:web
cd ../..

# 3. 原生 DSH 运行时
node scripts/build-fusion-native.mjs

# 4. 状态目录 + 记忆 Bot
export CORTICO_FUSION_STATE="$PWD/state"
npm run setup:memory

# 5. 配置与启动
cp config/config.example.json "$CORTICO_FUSION_STATE/deployment/config.json"
npm start
07 / LIMITS

先承认它
不完善。

这是一套真实部署，不是成熟产品。下面每一条都会影响你敢不敢把它放到生产环境。

Use with care / 研究型工程

它能工作，但不保证一直工作。

  • 接口会变。 Host、World 与记忆工具都在快速迭代，没有面向公众的稳定性承诺。
  • 部署是手工的。 构建上游、原生运行时、状态目录与 Provider，每一步都可能需要人看着。
  • 没有多租户隔离。 scope 是检索过滤，不是权限边界；一套部署默认服务一个所有者。
  • 默认只监听回环。 公网访问必须经过反向代理与 TLS，并保留 Web 密码。
  • 记忆不是“删一行”。 权威仓、副本、备份与索引要一起处理；删除需要审计回执。
  • 物理动作不可撤销。 canbot 之类的世界把“已受理 / 已写入 / 物理完成”严格分开，未知不会被猜成成功。
  • 崩溃恢复有边界。 未知结果保留原 operation ID，不自动重发；需要人工对账。
  • 没有保修。 AGPL 提供的是源码与许可，不是可用性、数据安全或模型行为的担保。
01 / 隔离先在独立机器或独立状态目录试，不要直接覆盖正在用的记忆库。
02 / 备份升级前做 SQLite 一致性备份 + 状态目录归档，并实际恢复一次。
03 / 最小暴露只开需要的 World，只给必要的令牌，公网入口放在反代之后。
