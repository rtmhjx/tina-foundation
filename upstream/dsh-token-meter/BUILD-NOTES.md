# Token meter overlay

Baseline: `runtime/dsh-0.1.5-rc.2/node_modules/@deepseek-ai/dsh-token-meter` version `0.1.5-rc.2`. Original bundled `lib/index.js` SHA-256: `f91bdd543a161cfbeec3450f44fc0ce310f5354b1be61d83dbce773d62ab011a`. `src/` is the pinned package's unbundled **distributed JavaScript**, not upstream TypeScript. `SOURCE-MANIFEST.json` records each source hash and the corresponding original distributed hash.

Run `node upstream/dsh-token-meter/build.mjs` from the workspace. This copies the JS/declarations from `src/` into `lib/types/` and bundles `src/index.js` to `lib/index.js` with esbuild, externalizing package dependencies. It does not alter the pinned runtime. The development `node_modules` junction resolves the pinned package's dependencies locally; do not deploy that Windows junction. This is a private patched package retaining upstream's version number; do not publish or treat it as byte-identical to upstream.

`measure(session, requestHeader?, { requestContext? })` returns effective `totalTokens` including the current head, `headTokens`, signed `headDeltaTokens`, `surfaceDeltaTokens`, baseline, and surface nodes. When the last successful request has a trusted recorded request context and last-attempt usage, the baseline stays provider input+output and the prior head estimate is replaced by the current head estimate. A missing historical context or missing last-attempt output falls back to estimated surface+current head. The contextPressure projection remains prompt-only and accounts for head changes; its state version is 5 so stale projections are replayed. Unchanged adapters without Cortico replay metadata preserve native per-attempt behavior. Cortico replay metadata with an unknown last input stays unknown; assistant attempts and interrupted settlements without a finish also stay unknown. Financial `tokenUsage` continues to use the original all-attempt billing total.

Callers must pass the actual planning `requestContext` as the third argument and must not separately add the full head. If omitted the meter uses the session's latest recorded context. Output reservation remains separate from the reported usage baseline. The original surface repricing and route pricing are retained; head messages use the same `estimateMessage` heuristic for both old and current snapshots, not an exact provider tokenizer. Avoid counting output reservation twice.

Verification: `node --test upstream/dsh-token-meter/test/pressure-overlay.test.mjs` from the workspace. This exercises the built actual module and real Session/ProjectionRegistry, plus failed attempts and billing folds; it does not establish production integration or real-provider usage correctness.
