# Coordinated CANBOT candidate: staging, upgrade and rollback

Status: candidate package only. Nothing in this document has been installed, enabled, or restarted. `coordinatedVoiceEnabled` defaults to false. The candidate uses Linux flock, a private Unix socket, an independently authenticated 7334 control endpoint and the existing microphone, STT and audio-play services. No Persona, Memory, main model, mobile app or ADB server change is included.

## Package verification

On an isolated Linux checkout of this package with Node 24 and Python 3 installed, run:

```sh
npm test
node scripts/write-describe.mjs
```

The official Cortico check on 5810 can be run from the installed Cortico release directory using `/home/tina/tina-runtime/bin/pnpm check:extension <absolute-candidate-package-dir>`. It constructs the default World only; it does not call `start()`, test Android or prove the opt-in settings work. Re-run tests and this check on the exact final staged package, then record its file hashes. For the media helper, record the SHA-256 of the actual installed candidate script and configure that exact hash; the code re-checks it before each playback. The helper's neighboring `shared_guard.py` and the microphone `stream_guard.py` must come from the same reviewed release.

Coordinate with the separate mobile task and preserve the shared ADB server. Do not launch a second owner, remove an existing socket or force-clear any unknown operation.
2. In a new private backup directory, preserve the currently active CANBOT World package and registration, current CANBOT and audio-play configuration, service startup environment and original playback helper. Preserve credentials with their original restrictive permissions in an appropriate private backup; never print or put their contents in event text or package artifacts. Note the exact package path, versions, process and config revisions and backup hashes. Do not copy mutable ledgers as if an in-flight transaction were a consistent snapshot; first obtain a safe quiescent state or record that it remains unknown.
3. Stage this package at a new versioned path; keep the old package intact. Stage `src/coordinated/canbot-play-wav-candidate.py` and its matching `shared_guard.py` together under a new protected directory, set executable permissions on the helper, and measure its hash. Set a separately generated `CORTICO_CANBOT_VOICE_TOKEN` through Cortico's supported secret mechanism; it must not be the avatar or media token. Restrict the 7334 bind address to the required robot LAN interface and account for bearer-over-HTTP confidentiality. Do not put a literal token in configuration or arguments.
4. Create private directories owned by the service UID for stream state/lock, spool, voice journal, arbitration journal and Unix IPC. IPC must be mode 0700; protect recorded audio and transcripts. The microphone guard and helper must both use precisely the `voiceStateDir`; configure `mediaPlaybackLinkPath` as the existing protected media-link JSON path, not its contents. Set explicit allowed playback roots to the observed audio-play materialization directory and verify it covers actual output without opening arbitrary paths. Configure the exact verified helper SHA-256. All paths must be absolute and verified as owned/protected. Review existing durable unknowns; do not discard them.
5. The current audio-play World is a separate process path with autoPlay enabled and currently calls the old playback helper directly. Point its backend, in the same controlled change, at `node <new-package>/src/coordinated/audio-ipc-client.mjs --file "{file}" --volume {volume}` and set `CANBOT_MEDIA_SOCKET=<mediaIpcDir>/media.sock` in the service environment. Verify the actual audio-play placeholder syntax and materialized roots from current live configuration first. Old direct helper invocations and other bypass media producers must be migrated, disabled or coordinated before enabling continuous mode; otherwise this package must remain disabled.
6. Confirm Android diagnostics supports the stream/lease/stop contract, screen and server agree on independent credentials and the 3000–60000 ms duration threshold, and all devices are reachable. Confirm the user's persistent mode preference and acknowledge that continuous mode can automatically start the microphone after an approved recovery. First enable with the user-observable recording state, after verifying that the previous operation is settled or explicitly isolated; never infer physical release from a software receipt. Complete the agreed test plan for actual recording, external events, playback pause/resume and interruption before marking operational.

## Rollback

If activation or verification fails, first stop making new voice/media requests and retain request IDs, unknown latches, chunks, outbox records and both journals. Check whether an Android operation, playback process or microphone stream is still in flight; a timeout or lost response does not mean it stopped. Use the exact operation receipt and safe stop/recovery procedures; do not reset ADB, delete a socket, unlock a journal, or replay a submission to force progress. If outcome remains unknown, keep the coordinated path unavailable and report it.

After the processes and operations are verifiably quiescent, restore the backed-up CANBOT package registration, configuration and original audio-play backend plus its prior environment in one controlled transition. Keep candidate files and new state available for diagnosis; do not overwrite or delete the old and new ledgers. Recheck service PID, ownership, authenticated health, World status, Android media state and an explicitly authorized speaker/microphone test. Restoring package configuration does not itself prove sound or physical stopping. Do not undo the separate mobile task's changes.

## Bounded storage and remaining verification

The candidate defaults to a 256 MiB audio snapshot capacity and a maximum of 4096 unresolved IPC admissions; both are configurable within validated bounds. Playback-confirmed snapshots can be retired only after the durable receipt is recorded; unknown snapshots remain. The arbitration journal retains the latest 128 detailed confirmed receipts and up to 65536 compact anti-replay markers; reaching a limit refuses further work instead of silently forgetting an ID. Continuous microphone chunks rotate only after audio processing and event delivery are confirmed. This bounds ordinary successful work but does not prove unlimited unattended stability, nor automatically clean uncertain or orphaned data. Reconnection submissions are durably latched before the side effect; an unknown survives process restart and stops auto retry. A safe, evidence-based operator recovery for unknown state remains a deployment prerequisite.

The offline fixture has verified a real CANBOT World, real stream engine and actual Python file lock with synthetic devices, not Android audio hardware. The package is not a released, mounted or device-accepted version. Review the official extension checker output: tag vocabulary may be unreachable; the extension check can pass while tag verification is skipped.
